checklist:
  - "Werk vanaf het eerste moment openbaar en volledig op basis van opensourcecomponenten."
  - "Bepaal de governance: van wie is de werkplek en wie heeft welke rol. Bijvoorbeeld: de opdrachtgever is eigenaar van de codebase, geeft die (leeg) vrij onder licentie en geeft de opdrachtnemer opdracht om eraan te werken door middel van bijdragen."
  - "Bepaal de werkplek (GitHub, GitLab of anders) en richt daar een repository in."
  - "Maak een LICENSE aan in de repository (EUPL 1.2)."
  - "Maak een openbare README met de functionele titel van het project."
  - "Beschrijf in de README de opdracht en de achterliggende vraag."
  - "Neem in de README de links op naar het beleid waaruit de opdracht is ontstaan."
  - "Beschrijf in de README de ambitie op het gebied van opensourcewerken en de huidige status."
  - "Beschrijf in de README de instructies voor developers, of verwijs ernaar."
  - "Maak een publiccode.yml aan."
  - "Maak een GLOSSARY aan voor termen en definities."
  - "Maak een STANDARDS aan voor de gebruikte standaarden."
  - "Maak een CONTRIBUTING aan voor bijdragen. Beschrijf daarin ook de verwachtingen, bijvoorbeeld over het gebruik van AI."
  - "Beschrijf in commit messages waarom je iets wijzigt. Wat er gewijzigd is, staat al in de diff."
  - "Werk vanaf het begin met geautomatiseerde tests en een hoge code coverage."
  - "Laat de code coverage bij elke bijdrage minstens gelijk blijven."
  - "Houd organisatiespecifieke vormgeving (kleuren, logo, namen, fonts) los van de rest van de codebase, bijvoorbeeld in configuratie en losse CSS."
